# Headless V3 engine (`vantage-headless`)

Server/daemon + thin CLI for the Opportunities ranking (Long V3, Long V2, Short),
built from this crate **without** Tauri/gtk/webkit:

```bash
cd apps/windows/src-tauri
cargo build --release --no-default-features --bin vantage-headless
B=target/release/vantage-headless

# daemon (market context OFF by default; add --market-context to enable it)
$B serve --profile sp500 --addr 127.0.0.1:7979 --data-dir ~/.local/state/vantage-headless

# client
$B status
$B rank --help                      # local, never contacts the daemon
$B rank --model v3 --top 20          # Android semantics (default): Act/Watch/Avoid + confidence
$B rank --model v3 --semantics tauri # desktop Opportunities list semantics
$B rank --model v2 --top 20 --json
$B rank --model short --top 20       # short labels: StrongShort…StrongAvoidShort
$B parity --model v3                 # snapshot round-trip check (desktop path vs snapshot); NOT Android parity
$B persist                           # POST; force-write the snapshot now (also every 60 s)
$B rank-snapshot ~/.local/state/vantage-headless/opportunity_snapshot.json --top 20  # offline replay
```

Profiles: `sp500`, `dow`, `russell`, `merval`, `nikkei`, `europe`, `asia`, `qa` (+ aliases).

## How it reuses the app

* `gui` cargo feature (default) carries Tauri and its plugins. `--no-default-features`
  drops them; `src/tauri_compat.rs` swaps `tauri::State` / `async_runtime` for
  std stand-ins so `commands.rs`, `regime`, `risk` compile unchanged
  (`#[tauri::command]` became `#[cfg_attr(feature = "gui", tauri::command)]`).
* `src/headless.rs` calls the app's own feed (`apply_universe_profile`) and the
  `get_opportunities` scoring body (`capture_opportunity_projection` +
  `project_opportunity_rows`); the list order mirrors `OpportunityList.tsx`
  (composite desc, stable).
* State: `history.sqlite` + `feed.log` (same as the app) and
  `opportunity_snapshot.json` (frozen scoring input, atomic write). After a
  restart the daemon serves the persisted snapshot until the live feed fills.
* Signal age: the Android and Rust Yahoo clients both stamp signals with age 0
  at fetch time and never age them, so the 30 s Stale gate does not fire on live
  data in either app; it only matters for injected/replayed signals (the fixture
  covers ages 0/5/30/31/3600).
* HTTP, std only, default `127.0.0.1:7979`. Non-loopback `--addr` is refused
  unless `--allow-remote` (there is no auth). `GET /status`,
  `GET /ranking?model=&semantics=&top=` (bad `top` → 400), `GET /parity?model=`,
  `POST /persist` (GET → 405). Without `--allow-remote` the Host header must be a
  loopback name (DNS-rebinding guard, else 421). One 5 s deadline for the whole
  request head (408), 5 s write timeout, max 16 concurrent
  connections (503 beyond).

## Android semantics (default for Long V3)

Ground truth is `apps/android/core`. `--semantics android` (default) ranks Long V3
as the Android Opportunities screen does; the Tauri GUI is unchanged and
`--semantics tauri` reproduces it. Long V2 and Short have no Android port here and
always use desktop semantics (the response says `"semantics":"tauri"`).

| Aspect | Android (headless default) | Desktop / Tauri |
|---|---|---|
| Universe (feed) | exactly Android's `assets/profiles/<p>.txt` (sp500 = 501, incl. `BRK-B`), compiled in; `serve --semantics android` (default) loads only these | + ETFs and crypto (572); `serve --semantics tauri` |
| Rows ranked | qualified only: profitable && gap ≥ 2000 bps | all rows |
| External signal | Stale > 30 s; Supportive iff gap(price, fair) ≥ 2000 | desktop thresholds |
| Confidence | not qualified/Stale/Divergent → Low; Supportive & ≥3 analysts (`weightedAnalystCount ?: analystOpinionCount`) → High; else Provisional | desktop |
| Forecast target | clamped weighted fair ?: external fair, weighted count ?: opinions | snapshot intrinsic, opinions |
| Decision | Low→Avoid; no upside→Watch; upside ≤0 or score <0→Avoid; trust note→Watch; High & ≥30→Act; else Watch | setup labels |
| Technicals | `ChartAnalysis.buildSummary` port on the 1y/1wk chart (`src/android_chart.rs`) | desktop chart summary |
| Fundamentals | `aggressiveV3FundamentalsScore` port (class exemptions, FCF/OCF yield vote, conv. silencing, coverage flag) | `score_fundamentals_v3` |
| Composite rounding | Kotlin `roundToInt` (half up) | `f64::round` |
| Tie-break | composite ↓, coverage ↓, confidence ↓, upside ↓, symbol ↑ | composite ↓, stable |

Parity is enforced by a shared contract: `shared/contracts/opportunity-v3-headless-fixture.json`
(generated by `tools/gen_headless_v3_fixture.py`) is scored by Kotlin
(`HeadlessV3ParityGoldenTest`, `HEADLESS_GOLDEN_WRITE=1` regenerates
`opportunity-v3-headless-golden.json`) and by Rust (`headless::android_parity_tests`),
which feeds the fixture through the real `ScreenerState` ingest and compares every row.
